# 信息核实 skill

> 双语 skill。English version: `SKILL.md`。英文是唯一权威源，`.zh.md` 是同步翻译——永远先改英文，再在同一次改动里同步到 `.zh.md`，绝不只改中文。

## 用途

用户给一句话或一段话需要核实。AI 不能「初步搜一下、看到几条网页摘要就脑补结论」。必须深挖到原始可信来源，或如实坦白核不到。

支持五类场景：

1. **基础真伪核实**：陈述里的数字 / 事实 / 引述是否准确
2. **完整性补充**：来源正确但用户引用断章取义，回补完整上下文
3. **一层推理核实**：直接数字找不到一手来源时，通过指标拆解（Z = P × Q）核算对账
4. **否定性陈述**：识别「X 从未做过 Y」这类不可证伪命题，改走「找反例」路径
5. **多源冲突**：两个权威源数字不一致时并列输出 + 解释差异

## 输入

用户给出一条待核实的陈述。可附补充文件（PDF、链接、截图、笔记）作为优先核对素材。

## 范围排除（拒绝核实的主题）

在开始任何核实工作前，先判断陈述是否落入拒绝核实的类别。下列主题无论用户怎么问、问得多具体，都直接拒绝：

- **政治问题** —— 选举、政党、政治人物立场、地缘政治争端、政府合法性辩论等
- **军事问题** —— 军事行动、兵力配置、装备数量、冲突细节、国防政策等
- **宗教问题** —— 教义、教派争议、宗教领袖表态、宗教间比较等
- **娱乐明星八卦** —— 个人生活、恋情、家庭、坊间传闻等
- **其他天然具有争议性的议题** —— 无论核实结果是什么，核实过程本身都可能引发争议

属于上述任一类别时，**只回复一行**并停止：

> 超出能力范围。(Out of scope.)

不要尝试核实、不要走部分核实、不要「我先试试看」、不要做分步分析。除这一行之外不解释、不提供变通方案、不建议替代提问。**那一行就是全部回复。**

这条检查在场景识别**之前**——一旦触发，skill 的其他逻辑全部跳过。

## 场景识别

内部把陈述归入五类之一，用来选对子流程（一层推理 / 否定性 / 多源冲突 各有自己的 emoji 标签）。**不要**把场景名作为单独一行打印出来——对用户没意义。同一陈述涉及多类时按主导路径处理，其余子情况一并说明。

## 回复语言

回复语言必须与用户提问的语言保持一致（用户中文 → 输出中文；用户英文 → 输出英文；混合时按用户问题的主导语言）。

Emoji 标签（`✅ ⚠ ❌ 🔎 ⚖ 🔒`）跨语言通用，不需要翻译。翻译跟在 emoji 后面的正文——如 `✅ Verified.` → `✅ 已核实。`。元数据字段名出现时也要翻译：`时点 / 口径 / 单位 / 范围 / 修订状态 / 数据类型` ↔ `Time point / Definition / Unit / Coverage / Revision status / Data type`。

内部逻辑、来源白名单、规则结构与语言无关——不要改。

## 工具调用说明（跨 LLM 适配）

本 skill 在不同 LLM 终端运行时，下列动作映射到各自的本地工具。表格只描述动作语义，不写死工具名。

| 动作 | 含义 |
|---|---|
| 通读全文 | 把 PDF / md / txt / csv 等文本读入并完整理解 |
| 抓取网页正文 | 从 URL 拉取页面文本（非搜索结果摘要） |
| 搜索引擎检索 | 用关键词在搜索引擎里检索 |

| 数据库查询 | 在结构化数据源中按字段查询 |

## 可信来源白名单

只接受以下类型的来源作为「核实成功」的依据。本节自包含，不依赖外部文档。

### 关于「代表清单 vs 穷举清单」

下文每个分类下的具体机构 / 网站 / 数据库列表只是**代表性示例**，不是穷举。**同等级别、同类性质**的官方机构与权威信息源同样适用——例如未列出的其他主权国家央行、国家级统计机构、知名国际智库、区域性权威媒体、行业一手数据库等。判断时按下面三条标准类比：

| 判断维度 | 接受 | 不接受 |
|---|---|---|
| **机构性质** | 官方（政府 / 央行 / 监管 / 国际多边机构）、权威专业（顶级智库 / 同行评审学术 / 主流投行咨询 Research）、独立第三方（声誉良好的聚合数据库） | 个人博客、自媒体、内容农场、SEO 站 |
| **内容性质** | 一手披露（年报 / 监管文件 / 政策原文）、一手统计（调查 / 普查 / 行政记录）、权威研究（带方法论的报告 / 论文） | 二手转述、机器抓取拼凑、AI 生成摘要 |
| **可追溯性** | 有明确机构署名、有发布日期、有原文 PDF / 数据库字段定位 | 匿名「据报道」「业内人士」、无原始链接、无定位 |

满足上述三条 = 可信源，即使未在下表中列出。仍受「不接受作为最终来源」清单约束（维基 / 知乎 / 个人博客 / 社交媒体 / 仅 SERP 摘要等）。

- 文本类（PDF / md / txt / csv）：通读全文
- 链接：抓取网页正文
- 图片：图像识别

### 不接受作为最终来源的「来源」

- 维基百科、百度百科、知乎、个人博客
- 未署名的媒体转述、内容农场、SEO 站
- AI 生成的摘要 / 总结（包括 ChatGPT、Perplexity、Gemini 等）
- 含糊措辞「据报道」「业内人士」「有消息称」「市场人士透露」
- 社交媒体内容（机构官方认证账号的正式公告除外）
- 二手转译，必须追到原始机构的官方版本
- 仅 SERP（搜索引擎结果页）摘要——必须点入原文确认，否则归入「无法核实」

### 中英文并重原则

国际机构 / 投行 / 咨询的官方报告主要英文。中国 / 中东 / 非洲等区域的本地数据与政策动态，中文一手资料常更准。政策文件原文（如沙特 Vision 2030）有官方阿拉伯文 + 英文版，必要时双版对照。核实时根据陈述涉及的地域 / 机构切换语言。

## 放弃判定标准

持续溯源，直到下面任一条件触发：

- **(a)** 在白名单内找到一手来源并（如需要）下载原文通读 —— 走 `✅ 已核实` 输出
- **(b)** 主流路径都试过仍未命中（直接搜关键词 → 换关键词与语言 → 追溯陈述里被引用的源头回到出版机构）—— 直接输出 `❌ 无法核实`，不得猜测、推断、用次级来源充数

没有固定的"层数预算"。**线索真正穷尽**时才停，不要按任意计数停。

## 下载原文规则

只看搜索引擎摘要、网页片段、二手转述就声称「已核实」不算数。涉及报告或图表时，必须把原文 / 原始数据下载到本地，AI 通读后再下结论。

触发条件（任一即触发）：

- 待核实陈述引用了某份报告（IMF Country Report、PIF Annual Report、央行 Working Paper、咨询白皮书等）
- 待核实陈述引用了某张图、某组数据、某个数字
- 待核实陈述引用了某项政策文本、监管文件、年报披露

下载步骤：

1. **定位原始文件**：优先机构官网原始链接，不要从二手转载点下
2. **下载到本地**：不预设保存路径。第一次下载前先询问用户保存位置；用户未指定时直接放在当前对话的工作目录下，命名 `<机构> <标题>.<扩展名>`
3. **通读后再判断**：通读 PDF 全文或抽全文摘要，把方法、关键参数、原文段落摘出来；数据读首尾若干行确认字段与口径
4. **图表来源**：若陈述指向某张图，必须找到该图所在的原始报告 / 数据库页面，下载后定位到图所在页码或数据表

### 图表「图意」核实

图存在 ≠ 用户对图的解读正确。下载后还要核：

- 坐标轴单位与口径（线性 vs 对数、绝对值 vs 同比、本币 vs 美元）
- 起始年份与基期（避免起点选择性误导）
- 是否累计 / 移动平均 / 经季节性调整
- 图注与脚注里的限定条件（"不含 X"、"仅 Y 地区"等）

若用户解读与原图含义不符，必须显式纠正。

### 下载受阻处理

AI 自动下载受阻时（403、付费墙、Cloudflare、需登录、地区限制、JS 渲染拿不到正文等），**先暂停核实**，按下面格式输出，把链接交给用户：

```
🔒 需要用户协助下载。
来源：<完整官方链接>
受阻：<付费墙 / 登录墙 / 反爬 / 地区限制>
请：下载后告诉我保存位置，或把相关段落粘到对话里。
```

用户提供后回到步骤 3 通读判断。**仅当用户也拿不到时**才走降级，输出时明确标注「未拿到全文，仅基于摘要核实，可信度降级」，不能冒充已核实。

反例（不接受的「核实」）：

- 「我搜到 Reuters 一篇文章说 PIF 资产规模 9250 亿美元，已核实」——Reuters 是二手转述，必须追到 PIF 官方年报原文并下载
- 「我看到 IMF 网站某页提到沙特财政平衡油价是 96 美元」——摘要不算，必须下载对应 IMF Country Report PDF，定位到具体表格与脚注

## 一层推理核实子流程

当陈述的直接数字找不到一手来源，但可以通过指标拆解推算来对账时使用。**仅做一层拆解**——拆出来的子指标必须能直接核到一手或聚合数据库来源。若子指标还要继续拆（多层推理），告诉用户超出 skill 范围，建议分步核实或人工接力。

步骤：

1. **拆解公式**：明确 Z = f(P, Q)（如 销售额 = 单价 × 销量；利润 = 营收 × 利润率；市场份额 = 公司销量 ÷ 市场总销量）
2. **分别核 P 和 Q**：每一项都按基础核实流程独立核到一手或聚合数据库来源
3. **核算 Z'**：用核到的 P、Q 计算 Z'
4. **对账**：把 Z' 与待核 Z 比较，定性判断（由 AI 估算，不写死百分比阈值）
   - 基本一致：偏差在合理范围内
   - 显著偏差：偏离明显，需要解释
   - 严重不符：差距大到怀疑陈述本身有问题
5. **偏离归因**：若不一致，分析哪个细分指标的假设最可能是问题源；P、Q 的口径 / 时点 / 范围是否一致

输出格式：

```
🔎 一层推理核实。Z = f(P, Q) → Z' = <算出值>；陈述 Z = <用户值>；<基本一致 / 显著偏差 / 严重不符>。
P = <值>，来源：<机构 + 链接>
Q = <值>，来源：<机构 + 链接>
[⚠ 归因：<仅在偏离时——指出问题源 + P/Q 口径 / 时点 / 范围是否一致>]
```

## 否定性陈述特殊处理

识别陈述含「从未」「没有」「未曾」「不曾」「无」等否定限定时，先告知用户：

> 这是一条否定性陈述。负面陈述几乎无法用搜索证伪——找不到反例不等于证实成立。我会尝试找反例：找到反例 = 陈述被推翻；未找到反例 = 不能给「已核实」标签，只能说「未发现公开反例」。

之后走「找反例」路径，仍按白名单与放弃判定标准执行，输出标签调整为：

- `❌ 陈述被推翻。<反例 + 一手来源>` —— 明确否定
- `⚠ 未发现公开反例。` —— 注明「未找到 ≠ 证实」，列 2-3 个已查的关键词 / 站点

## 多源冲突子流程

两个白名单内来源对同一数字给出不同值时，**不强行选一个**。并列输出：

```
⚖ 多源冲突：<陈述>
A：<X> —— <机构 + 链接>
B：<Y> —— <机构 + 链接>
差异：<最关键的 1-2 个原因——口径 / 时点 / 修订状态 / 范围>
建议：<让用户基于场景选择，或明示需要哪种口径>
```

## 元数据：差异时才显式标注

内部对每条核实都过一遍下面六个维度。**默认不打印**——与用户提问完全一致时，列出来只是噪音，不增加洞察。

**只在某个维度与用户陈述 diverge、或非常规以致可能误导时，才单写一行 `⚠`**。该写 `⚠` 的例子：

- 用户问「沙特 2023 GDP」，实际找到的是 **非油 GDP** → 标注 `口径` 差异
- 用户问「2024 Q4」数据，但找到的是 **初值，尚未修订定稿** → 标注 `修订状态`
- 数字是 **target / forecast**，不是 actual → 标注 `数据类型`
- 币种 / FY-vs-CY / 合并 vs 母公司 / 范围错配 → 对应标注

| 维度 | 何时需要标注 |
|---|---|
| **时点** | 来源里的年 / 季 / 截至日 ≠ 用户暗示的时点 |
| **口径** | 统计范围 / 计算方式（名义 vs 实际、含某项与否等）有差异 |
| **单位** | 币种 / 量纲容易混淆时（亿元 vs million、FY vs CY） |
| **范围** | 地理 / 业务覆盖比用户暗示的更窄 / 更宽 |
| **修订状态** | 初值 / 修订值 / 最终值——可能让用户混淆 vintage 时 |
| **数据类型** | actual / forecast / projection / target / estimate——只要不是 `actual` 就标 |

这条规则替代旧的"必须填六项"。**关键是 surface divergence，不是机械列六个字段**。

## 输出格式

输出要紧凑。常见场景目标是 3-5 行；只在确有差异时（参考元数据节）加一行 `⚠`。

### ✅ 已核实

```
✅ 已核实。<一句话核心结论，自然语言>。
来源：<机构 + 报告名>（<YYYY-MM>, <页/表/图定位>）→ <本地路径，如已下载>
原文："<逐字摘录支撑该陈述的关键句>"
[⚠ <一行，仅在某个元数据维度与用户陈述 diverge 时——例如"该口径为非油 GDP，不是整体 GDP">]
```

### ⚠ 部分核实

```
⚠ 部分核实。
已核实：<子句> —— <来源>
未核实：<子句>
建议：<让用户补出处 / 改写为「待核实」 / 剔除>
```

### ❌ 无法核实

```
❌ 无法核实。<推测原因，一句话>。
已试：<2-3 个最相关的搜索 / 站点 / 线索>
建议：<请用户提供原文 / 改写弱化确定性 / 剔除>
```

四个子流程的输出 —— `🔎 一层推理核实` / `❌ 陈述被推翻`、`⚠ 未发现公开反例` / `⚖ 多源冲突` / `🔒 需要用户协助下载` —— 按各自上面定义的格式输出。

## 红线

- **不造数**：宁可输出「无法核实」，不要给似是而非的数字或日期
- **不替换口径**：用户问的是 A 口径，找到的是 B 口径，必须显式标注差异，不可隐式替换后冒充核实成功
- **不引非白名单**：维基、转述、AI 摘要、社交媒体均不能作为最终来源
- **不省略链接**：每条已核实结论必须能让用户点回原始页面或定位到本地文件
- **区分三态**：明确区分「事实」（白名单内有原文）/「估算」（有方法但参数推算）/「推断」（无直接来源，只是合理猜测）。后两种不能写进「已核实」
- **不靠摘要核实**：涉及报告 / 图表 / 数据的陈述，必须下载原文到本地并通读后才算核实。只看 SERP 摘要、网页片段、二手转述就声称「已核实」是越线行为
- **不冒名个人立场**：学者个人 working paper / 个人观点 ≠ 所属机构官方立场，不能混淆
- **不跳过下载受阻提示**：自动下载失败时必须按 `🔒 需要用户协助下载` 格式把链接交给用户，不能省略提示直接走降级或编造
- **不超出一层推理**：本 skill 仅做一层指标拆解（Z = P × Q）。若子指标还要继续拆（多层推理），告知用户超出 skill 范围，建议分步核实或人工接力
- **差异必须 surface**：六个元数据维度（时点 / 口径 / 单位 / 范围 / 修订状态 / 数据类型）任一与用户陈述不一致时，必须写一行 `⚠` 提示。**默认不打印**这六项，但**差异时不打印 = 隐式口径偷换 = 越线**
- **不核实拒绝类主题**：政治 / 军事 / 宗教 / 娱乐明星八卦 / 其他天然具有争议性的议题超出能力范围。直接回复「超出能力范围。(Out of scope.)」并停止——不走部分核实、不提变通方案、除这一行之外不解释
